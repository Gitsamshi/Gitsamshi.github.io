THE DESIGN-DECISION TREE

organized by engineering decisions, not surface categories

A model is not a category — it is a vector of technical decisions. The usual buckets (any-to-any, voice, U+G…) describe what a model is for; they hide what a model is. Read the papers and four orthogonal forks fall out: representation · fusion · generation · real-time speech. Each tab is one fork; every model hangs under the option it actually chose. The same model recurs across tabs — hover it to see its full signature. ~40 nodes, all decisions verified against the arXiv source.
